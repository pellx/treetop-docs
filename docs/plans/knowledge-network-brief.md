# 交互思维导图：需求与方案评审依据

日期：2026-11-15
状态：已进入详细方案阶段，尚未实施网页功能。
主项目：`treetop-docs`。

## 用户明确提出的目标

1. 在现有 HTML 文档网站中实践此前讨论的思维导图。当前委托 VPS 上的 Claude Code 使用 Fable 制定更详细方案，范围仅限思维导图及其与知识点内容的联系。
2. 教科书思维导图作为参考，但不照搬排版。网页需要承载更细的知识关系及可交互的信息层次。
3. 支持从中心向四周发散的整体视图进入局部：选择一个子节点后，可以改变整体布局，展开子集信息，并隐藏或简化部分主干。
4. 可以链接到具体知识点／考点，查看其考试关联，例如更多用于大题还是选择题。题型倾向需要有依据，不能把无来源的判断当统计事实。
5. 同一知识内容可以按不同逻辑组织：知识点之间的关系；某种具体大题所涉及的知识；不同知识点推导逻辑的相似性。
6. 保留此前的工具目标：直观看懂复习范围与串联关系、高效寻找和直达内容、便捷返回导图并继续使用。
7. 设计应从现有工具不直观、不好用的具体问题出发，探索新颖且实用的表现形式。
8. 最新澄清：参考图受教材编排限制，主要是知识小节图。最终产品必须提供每本书各自的完整思维导图，以及整个生物学科的跨册思维导图；不能把一个小集合或小节示例当作最终范围。
9. 学科图与全书图都属于原有 `treetop-docs` 的一部分，是更智能的索引，与既有文档、目录、搜索和播放器共存，不能独立成另一个网站或替换讲义。
10. 当前继续委托 Fable 探讨如何呈现全书与学科级网络，不开始原型或网页实现。既有约33节点集合只可作为验证局部交互的案例。
11. 后续具体文件编写与实现由 Opus 负责；本轮只形成可交接的方案，不启动 Opus 实现任务。

## 沿用的内容原则

- 考法分类不严格受教材章节限制，应按知识关联形成集合。
- 与考法关联时侧重答题方法和答案书写方式，但本次不扩展为完整考法内容库建设。
- 用户当前重点是选择性必修二《生物与环境》。已有讲义作为内容来源，不重新创作全套讲义。
- 高考后协作 Wiki 是长期规划，本轮不开发编辑后台或协作机制。

## 当前假设与尚缺材料

- “多个表格”暂理解为多张导图／多种组织视图，不固定成传统表格界面；表格可作为辅助索引候选。
- 已收到用户提供的21张 JPG 参考导图，位于工作区根目录 `生物思维导图/`。原图已上传到 VPS 规划任务的独立资料目录，逐张 SHA-256 校验通过。Fable 已恢复原会话，需逐张阅读，并区分参考图内容、现有讲义内容及新增设计建议。图片不作为网站公开资源发布。
- 尚未提供用于统计题型倾向的真题数据集。任何示例题型标签都应明确来源、状态与适用范围。
- “主干移到一侧、另一侧显示详情”仍是交互示例，不是必须采用的唯一布局。

## 当前项目约束

以 `CLAUDE.md`、`README.md` 和现有代码为准：

- 纯静态 HTML、CSS、原生 JavaScript；站点不依赖外部网络，无构建步骤。
- GitHub Pages 子路径部署，站内资源与链接使用相对路径。
- 当前由 `assets/js/app.js` 处理外壳路由、正文 iframe 通信与语音播放；深链示例为 `index.html#/xb2-12/p1`。
- 正文滚动可通过消息让外壳用 `history.replaceState` 更新考点地址。导图返回与浏览器历史必须考虑现有行为。
- 保留既有内容、目录、搜索、语音连播、深链及主题同步。避免与现有空格键、方向键等播放器快捷键冲突。
- 保持直角边框，不破坏现有生物图示几何结构。

## 评审详细方案时需要核对

- 三种视图是否复用稳定的知识身份，并区分层级、因果、任务关联和推导类比。
- 是否明确总览、选中、聚焦、展开、详情、进入讲义和返回的操作差别。
- 是否解释重排时哪些节点保留、隐藏和折叠，以及快速连续操作的处理。
- 是否能恢复视图、焦点、展开状态与视口，兼容浏览器前后退、刷新和直接深链。
- 示例链接是否对应真实的本地页面与考点锚点。
- 是否清晰区分真实题型统计、人工经验和数据缺失。
- 是否有适合静态站点的接入方式、可维护数据结构和有界的首版范围。
- 是否包含手机、键盘、减弱动效、主题和离线使用的验收要求。
