# 思维导图优化方案：主框架、知识联系与二级展开

日期：2026-11-17

状态：需求与实施建议，交给后续 agent 实现；本次不修改网页功能。

## 1. 本次目标与明确要求

现有思维导图在书本、章节及大的知识板块之间的定位和连接表现较好，应保留这套能力。在此基础上，让导图能够解释知识之间的内在联系，帮助读者理解和串联知识。

用户明确要求：

- 保留现有册目、大知识板块的表现形式，有主框架标明知识点所处位置。
- 参考教材导图对知识逻辑的表达，展示知识点之间的内在联系，不止提供另一种目录入口。
- 提供几个可以启用的按钮，让读者选择展示哪些知识联系。
- 支持同时展示二级子节点，避免总是只有一个大节点连着一圈直接子节点。
- 教材参考图受篇幅、编排限制，主要是局部知识块的导图；借鉴其内部连接逻辑，不能因此把全书、跨册能力缩成几个孤立小图。
- 交给实施 agent 的资料必须包含参考图片原文件，不能只交一份提到图片路径的文字。

以下具体按钮分组、默认展开策略、实施顺序是建议，不是用户已经指定的最终界面细节。后续可以调整，但必须满足上述目标。

以当前代码为准，旧方案仅作背景：

当前并非完全没有关系与二级展开：

- `relTypes` 已有组成、因果·影响、先后、实例·依据、基础·依托、对比、类比、跨尺度对应、原理→应用等类型。
- `renderGraph` 在局部图选中节点后，会绘制与该节点相关的关系；图外端点以关联入口呈现。不能把“关系已经写进数据”视为“知识网络已经直观展示”。
- 学科总览已有可叠加的跨册主线按钮，但这些主题主线与具体关系类型不是同一个维度。
- 局部布局已有 `child` / `grand` 两级，`defaultExp` 在部分情况下自动展开；总览布局仍主要为中心与第一圈节点。本次需要让二级结构在合适场景下更直接、稳定地可见。

因此应增强现有模型与呈现方式，不重建另一套互不相通的导图。

## 3. 视图组织：稳定主框架上展示知识关系

### 3.1 主框架负责定位

保留学科、本册和局部范围之间的连续导航。框架说明“这项知识在何处”，包括当前范围、祖先路径、所属板块以及必要的相邻板块。框架边表示编排归类，不自动解释为生物学上的组成、因果或前提关系。

进入局部后，可以将主框架收拢到侧边或保留为紧凑的上级路径，但应始终能看出来源、返回上级、定位到所属书册。继续保留现有平移、缩放、回正、搜索定位、快速跳转和讲义往返能力。

### 3.2 知识关系负责解释

局部图应能在未逐个点击节点时，直接展示当前范围内已启用的知识关系。关系可跨越不同父节点或不同板块；一项知识可以同时参与多条关系，不强行压成单父级树。

每条关系应能读成一句有意义的话：起点知识 → 关系词 → 终点知识。例如现有数据中的“出生率、死亡率、迁入率、迁出率 —直接决定→ 种群密度”。显示方向以数据的 `from` / `to` 为准，不能随当前选中节点改变。

- 有方向的因果、过程、应用关系显示箭头与关系词。
- 对比关系显示比较维度，不用单向箭头暗示因果。
- 双向作用或反馈需要明确各方向含义；不能给任意连线加双箭头来表示“有关”。
- 编排框架线与语义关系线在样式、图例和文字上可区分，不能只靠颜色。
- 选中节点后突出其关联链路，其他已启用关系可以淡化；取消选中后恢复该范围的关系全貌。
- 关系条件、依据与更长解释放入详情，图上保留简洁且准确的关系词。

### 3.3 跨范围关系

关系端点在折叠分支、其他章节或其他册时，显示可追踪的入口及所属位置。读者可展开有关分支或跳到目标范围，返回后恢复原来的展开、筛选和视口状态。

总览可聚合跨板块关系，并显示关系数量及可展开入口。聚合只说明板块内知识之间存在这些关系，不将某条局部因果泛化为两个整章之间的因果。不把图外关系静默丢弃，也不一次性把全站细节铺满画布。

## 4. 可启用按钮：关系类型与主题主线分开

建议提供“关系类型”按钮组，允许多选叠加。以下为首版候选分组，可结合样例及实际数据调整：

| 建议按钮 | 对应现有类型 | 图上应表达的内容 |
|---|---|---|
| 组成与基础 | `compose`、`basis` | 组成、载体、依托；具体关系词仍区分这些含义 |
| 因果与影响 | `cause` | 谁影响谁、在什么条件下影响；调节或反馈需有明确依据 |
| 过程与顺序 | `seq` | 过程先后、步骤衔接；不把时间先后当成因果 |
| 对比与类比 | `contrast`、`analogy` | 对比维度、相似结构及不可互换的差异 |
| 实例与应用 | `instance`、`apply` | 具体实例、证据、原理的应用 |
| 跨尺度联系 | `scale` | 同一过程在不同生命系统层次上的对应 |

交互建议：

- 主框架持续保留；关系按钮控制其上叠加的语义关系。关系开关与分支展开相互独立，关闭关系不收起已经展开的二级节点。
- 现有“能量”“调节与反馈”等主题主线继续保留，并与关系类型分组标识，避免读者混淆“看什么主题”和“看什么关系”。
- 局部默认展示一组有依据的核心关系；具体初始组合由样例验证决定，不能默认又退回只有目录线的状态。
- 提供恢复默认或清除关系叠加的操作。切换按钮时保留焦点、展开和视口，不把整张图重新洗牌。
- 按钮有明确启用状态、可用关系数量和键盘操作；当前范围没有某类关系时说明暂无数据。
- 在手机上可折行或收纳按钮，但不要遮挡图、详情或现有底部控件。

## 5. 二级子节点

这里的“二级”指相对当前中心或焦点的“子节点 → 孙节点”，不是单纯换到下一张图后再显示一圈节点。

- 总览允许原地展开某个一级分支，同时看到其二级节点和其他主分支，继续看清它在全图的位置。
- 局部范围在内容量允许时同时显示焦点、一级子节点和二级子节点，并绘制这些节点之间已启用的真实关系。
- “选中看详情”“展开下级”“进入该节点作为新焦点”应有清晰、可区分的入口。
- 二级节点可以与其他分支中的节点连接，不局限于连接自己的父节点。
- 数据密集时按分支展开、折叠并标明隐藏数量；通过平移、缩放或进入局部查看，避免把全图强制缩到文字不可读。
- 没有下级的节点不伪造二级内容；缺少整理内容的板块保留可达的目录兜底，并明确状态。
- 折叠含有关联端点的分支时保留关系入口或汇总提示，不能让读者误以为关系不存在。

## 6. 内容整理原则

教材图片用于提炼关系表达与局部组织方式，网站讲义提供已有知识与跳转落点。实施时应逐张阅读样例，区分“图片明确展示”“站内讲义可查”“整理者新增建议”。

- 复用稳定概念 ID；同一知识出现在多个章节时用引用和多位置映射，不复制成互不关联的概念。
- 保留关系的 `type`、`label`、`status`、`basis` 与必要的 `condition`。关系依据不足时标待核，不能根据名称接近自动认定因果。
- 不直接把教材的所有分类线归为 `compose`；“归类”“组成”“发生在”“促进”“抑制”等含义应区别表达。
- 如需补充更细概念，明确其所属位置、讲义落点和引用依据。图中二级展示应来自有效内容，不通过机械拆标题凑层级。
- 参考图片可作为整理来源记录，但现有 `status: site` 仍必须满足站内引文规则；新增图片来源格式时同步调整校验，不冒充站内已核验。
- 不扩写完整讲义、不重做播放器、不引入题型统计或协作后台。原有“大题任务”“推导方法”组织模式保留兼容。

## 7. 实施顺序与交付要求

1. 阅读本方案、全部参考图及现有实现，列出可复用能力与需要补充的关系数据。
2. 选一个包含分支间联系和二级节点的局部样例验证布局；建议优先选选必二中已有关系数据较充分的种群或生态系统内容。另选一个跨章或跨册实例验证主框架定位。
3. 完成关系筛选、方向与标签、二级原地展开、图外关系入口和状态恢复，再扩展到各册框架。
4. 数据完善与渲染能力分别验收：首个局部样例仅是验证切片，不代表全书、全学科内容已整理完成。未整理区域仍可访问，明确已完成范围。
5. 交付可运行修改、涉及文件说明、已整理关系范围、依据检查结果、桌面与手机演示及仍未整理的内容。更新使用说明中的关系按钮与展开操作。

继续遵守项目约束：静态 HTML/CSS/原生 JavaScript、相对链接、直角边框；保留搜索、讲义深链、原音频与连播、主题同步及既有内容。
